# 1С-агент — бриф для ИИ

Ты пишешь BSL и через MCP `1c-agent` гоняешь его в живой 1С, правишь расширения/основную
конфигурацию, гоняешь YaXUnit. Строка подключения к базе приходит ТОЛЬКО из чата — в конфиге её нет.

## Старт сессии
1. `preflight()` — одна сводка: платформа, компилятор-база, HTTP-эндпоинт, раннер (транспорт/режим), `verdict`.
2. Раннер не на связи → попросить человека открыть `ВнешняяОбработка.epf` в базе (или `Раннер_*.bat`). Не чинить самому.
3. `ib_connection` — строка из чата, ЯВНО в каждом вызове. `Usr=` — ТОЧНЫЙ логин ИБ (`list_ib_users()`), иначе headless-вызов виснет на диалоге навсегда.
4. Дальше `run_module` / `query_data`; несколько независимых заданий — `run_module_batch`.
5. Тесты YaXUnit — только по просьбе; перед первым тестовым модулем `get_guide("yaxunit_tests")`.

## Задание для run_module
```
Процедура ВыполнитьЗадачу(ЛогВыполнения) Экспорт
    Сообщить("...");      // ЛогВыполнения — СТРОКА
    Сообщить("ГОТОВО");   // обязательно
КонецПроцедуры
```
- Внутри задания НЕТ объявлений `Процедура`/`Функция` и НЕТ `Возврат` — иначе медленный путь через сборку .epf (+3.4с) или отказ. Помощника вставляй по месту.
- К конфигурации полными путями (`Документы.X`, `Справочники.Y`), выборка `.Выбрать()`.
- `on_client=True` — только для форм (`ОткрытьФорму`, `.Открыть()`); только HTTP-транспорт, только быстрый путь; вывод пиши в `ЛогВыполнения`, `Сообщить()` там не собирается.
- Безопасный режим (флажок на форме раннера) запрещает `Удалить()` — для удаления флажок снять.
- Вывод — поле `output` результата. `work/logs.txt` руками не читать.

## Ловушки BSL (каждая стоила прогона)
- `И`/`Или`/`Не`/`Знач` зарезервированы — не имена переменных.
- Тернарника нет: `?(Усл, А, Б)`.
- Запрос: нет подзапросов в списке выборки; поля неограниченной длины нельзя в `СГРУППИРОВАТЬ ПО`; алиас ТЧ ≠ имя ТЧ владельца (`КАК Т1`).
- `СтрокаТаблицы["Кол"]` нет — `.Получить(Индекс)`; `Метаданные.<Вид>.Найти(Имя)`.
- `Структура.Свойство("Имя", Приёмник)` — приёмник только локальная переменная.
- `ЮТест.Данные().СоздатьДокумент()` возвращает Ссылку (ТЧ read-only) — заполнять через `КонструкторОбъекта`.
- Формы в расширении: программные реквизиты только `ЭтаФорма["..."]`; событие вешать в Form.xml; см. `get_guide("extension_forms")`.
- Обычное приложение (8.2-совместимость): методов может не быть на этапе КОМПИЛЯЦИИ — звать через `Выполнить()`; `ВнешниеОбработки.Подключить` нет → `Создать(путь, безопасный)`; обработчик обычной формы работает только если назначен в палитре.

## Ловушки инструментов/платформы
- **Файлы правим Write/Edit, не bash-heredoc** — слой инструмента схлопывает `\` (`"\task"` → таб).
- **.epf разбирать/собирать ТОЛЬКО в родной базе** (`ib_connection`), не в `compiler_db`: чужая база тихо схлопывает ссылочные типы реквизитов в строку; `write_epf_form_module`/`patch_epf_form_module` откажутся при потере типов (`allow_type_loss=True` снимает — не снимай без просьбы).
- **Боевые базы удалённые** — сервер 1С не видит локальных путей. Файл в базу → `upload_file_to_runner`. Исходники по диску не искать — спрашивать у человека.
- После деплоя базу ОСВОБОЖДАТЬ (не поднимать раннер) — человеку нужен конфигуратор.
- `LoadConfigFromFiles` и `UpdateDBCfg` — раздельными вызовами. Пустой /Out-лог ≠ успех.
- `UpdateDBCfg` на файловой базе — монопольно: сначала `kill_sessions`. DESIGNER-изменения уже открытая сессия не видит → `restart_runner`.
- Обновление объекта основной конфигурации сохраняет uuid (`_preserve_existing_ids`) — не ломать.
- «Объект существует» = файл на диске И тег в `Configuration.xml`.
- Неудачный `UpdateDBCfg` не откатывает `LoadConfigFromFiles` — диалог «Конфигурация не соответствует» ловится `screenshot_1c_window`.
- Долгий Dump/RunUnitTests ≠ зависание: смотри `screenshot_1c_window`, не гадай по времени.
- XML «загрузилось» ≠ «работает». Формат нового узла угадан неверно 2 раза → не гадать, просить у человека реальный дамп.
- Безопасный режим расширения снимается только `РасширенияКонфигурации...БезопасныйРежим=Ложь` — не обходить без просьбы.
- `taskkill` — через PowerShell, не Git Bash (`/PID` превращается в путь).
- `ws=` (веб-публикация) — только группа A (раннер), конфигуратор по ws не ходит.
- `lint_module` ловит синтаксис, но не клиентскую недоступность метода (`ПолучитьСообщенияПользователю` нет в тонком клиенте) — клиентский код проверять открытием.
- `xr:ClassId` в XML обработок — фиксированный, подменять нельзя; свой только uuid объекта.
- Сборка .epf: `LoadExternalDataProcessorOrReportFromFiles` понимает только ПЛОСКУЮ выгрузку.
- После правки любого .py — перезапустить MCP-сервер, после правки раннера — переоткрыть .epf в базе.
- Двух процессов mcp_server.py — норма (второй становится клиентом первого); `http_transport_status.mode` покажет.

## Правила
- Решил новый случай руками (формат XML, новый вид объекта) → задача закрыта только после: паттерн в `guides.py` + инструмент, если повторится. Иначе следующая сессия платит те же 15 минут.
- Чего-то не хватило в инструментах / упёрся в ограничение → запись в `TASKS.md` раздел «Чего не хватило» (дата, инструмент, что именно). Не молчать.
- Частные задачи клиентов — НЕ в этом репозитории (папка `D:\1сБазы\работа\<задача>`).

## Карта кода
`mcp_server.py` → `src/tools/*` (тонкие `@mcp.tool`) → `src/onec/*` (логика: `glue.py` раннер/run_module,
`metadata_deploy.py` объекты основной конфигурации, `extension_deploy.py` расширения, `epf_build.py` .epf,
`http_transport.py` эндпоинт раннера, `guides.py` тексты get_guide). `src/core/` — конфиг/подключение.
`ВнешняяОбработка/` — раннер управляемого приложения (плоский исходник + .epf), `ВнешняяОбработкаОбычная/` —
раннер обычного приложения (сборка `python tools/build_ordinary_runner.py`). `runtime/`, `work/` — не в git.
