# 1С-агент — MCP-сервер для вайб-кодинга под 1С:Предприятие

Claude (в чате/Claude Code/Claude Desktop) через этот MCP-сервер пишет BSL и
гоняет/чинит код в **живой базе 1С**, подключает и правит расширения, создаёт
объекты основной конфигурации (справочники, документы, регистры...), гоняет
YaXUnit-тесты — без ручного open-Configurator-click-click. Claude — дирижёр,
сервер — руки: тонкая обёртка над `1cv8.exe DESIGNER`/`ENTERPRISE` CLI.

Опционально: локальная Qwen2.5-Coder-7B (через [LM Studio](https://lmstudio.ai/))
как дешёвый автоматический починщик мелких синтаксических ошибок — не
обязательна, без неё всё остальное работает как есть.

Документы для ИИ (не для человека): [HANDOFF.md](HANDOFF.md) — короткий бриф и
ловушки, [TASKS.md](TASKS.md) — открытые задачи и «чего не хватило в инструментах»,
[HANDOFF_ARCHIVE.md](HANDOFF_ARCHIVE.md) — история по тикетам. Этот README — для
человека, который хочет поднять сервер у себя.

## Требования

- **Windows** (сервер использует `subprocess`+PowerShell+WMI, `pywin32`) —
  других ОС не поддерживает.
- **1С:Предприятие 8.3** установлена и лицензирована на этой машине (сервер
  просто вызывает её `1cv8.exe` — сам ничего не эмулирует и не обходит
  лицензирование/аутентификацию).
- **Python 3.10+**.
- **Java 17+** — только для `lint_module` (BSL Language Server); без него
  остальные инструменты работают, `lint_module` просто вернёт ошибку.
- **[LM Studio](https://lmstudio.ai/)** на `:1235` с моделью Qwen2.5-Coder-7B —
  только для `heal_module`/`fix_snippet`; без него оба инструмента деградируют
  до "прогнать код через 1С один раз, без автопочинки" (см. `qwen_available()`).

## Установка

```bash
git clone <этот репозиторий>
cd 1cAgent
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

Дополнительно — скачать руками (лицензионные/сторонние бинарники, в git не
входят) и положить в `tools/`:
- [`bsl-language-server.jar`](https://github.com/1c-syntax/bsl-language-server/releases/latest)
  (файл `*-exec.jar`) — для `lint_module`.
- [`YAxUnit.cfe`](https://github.com/bia-technologies/yaxunit/releases/latest) —
  расширение для YaXUnit-тестов, подключается через `attach_extension`.

## Настройка путей

`src/core/config.py` сначала пробует захардкоженный путь к `1cv8.exe`/`java.exe`
(строки `_PATH_1C_HINT`/`_JAVA_HINT` — под конкретную машину автора), и только
если его нет на диске — автопоиск по стандартным папкам установки
(`bootstrap.py:find_1c_platform`/`find_java`). На новой машине проще всего
поправить `_PATH_1C_HINT`/`_JAVA_HINT` под свой путь, либо просто ничего не
трогать — сработает автопоиск, если платформа стоит в стандартной папке.

`ib_connection` (строка подключения к РАБОЧЕЙ/тестовой базе — не путать с
`compiler_db`, служебной пустой базой для сборки `.epf`) НИГДЕ не хардкодится —
передаётся явно в каждом вызове, который его принимает. Формат — стандартный
1С: `File="C:\путь";` (файловая) или `Srvr="сервер";Ref="база";Usr="...";Pwd="...";`
(серверная).

## Подключение к Claude

Скопируйте [`claude_desktop_config.example.json`](claude_desktop_config.example.json),
подставьте реальный путь к проекту, и добавьте содержимое `mcpServers` в свой
`claude_desktop_config.json` (Claude Desktop) — или зарегистрируйте тем же
способом в Claude Code (`.mcp.json` проекта или `claude mcp add`). Команда
запуска — `.venv\Scripts\python.exe mcp_server.py` (stdio-транспорт).

## Первый запуск

Первое, что стоит попросить Claude сделать в новой сессии — `preflight()`:
одна сводка по окружению (платформа/компилятор-база/HTTP-эндпоинт/раннер) и
вердикт, можно ли работать. Бриф для ИИ сервер отдаёт сам при подключении
(`INSTRUCTIONS` в `src/tools/core.py`), полная версия — [HANDOFF.md](HANDOFF.md).

## Безопасность и границы

- Код, который Claude гоняет через `run_module`/`heal_module`, исполняется в
  **принудительном безопасном режиме** 1С (защита от произвольного файлового
  I/O из LLM-сгенерированного кода) — единственная точка входа:
  `Процедура ВыполнитьЗадачу(ЛогВыполнения) Экспорт ... КонецПроцедуры`.
- `screenshot_1c_window` — ТОЛЬКО ЧТЕНИЕ: снимает окно 1С, но никогда не шлёт
  в него клавиши/клики. Закрытие зависшей сессии — через `kill_sessions`,
  не автоматическое подтверждение диалогов.
- `kill_sessions` не трогает интерактивные сессии, которые человек открыл
  вручную (Конфигуратор/клиент) — завершает только процессы, запущенные самим
  сервером (форма-раннер/`RunUnitTests`).
- Телеметрия (`runtime/telemetry.jsonl`, лог каждого вызова инструмента)
  пишется ТОЛЬКО локально на диск, никуда не отправляется; пароли (`Pwd=...`
  из `ib_connection`) маскируются перед записью.
- `runtime/`, `work/`, `tools/*.jar`/`*.cfe` — не в git (см. `.gitignore`),
  там живут дампы реальной конфигурации и лицензионные бинарники третьих лиц.

## Известные ограничения

- Только Windows.
- OCR для чтения текста с диалогов 1С не подключён (нужен `winsdk`, не
  собирается под свежие версии Python без Visual Studio) — Claude читает
  скриншот напрямую как изображение, без распознанного текста.
- Живое end-to-end тестирование в основном проводилось на файловых базах;
  серверные (`Srvr=...`) — тоже поддерживаются кодом, но меньше "обкатаны".
- Границы охвата инструментов для объектов основной конфигурации (что именно
  автоматизировано, а что нужно собирать руками) — см. докстринг
  `src/onec/metadata_deploy.py`.

## Лицензии

Сервер автоматизирует ВАШУ собственную лицензионную установку 1С:Предприятие —
не обходит лицензирование, не эмулирует платформу. Исходники типовых
конфигураций (1С:ERP и т.п.) в репозиторий не входят и не должны — если
используете их как справочный материал (инструмент `search_reference`),
держите такой дамп локально, вне git.
